## 三个 P0 的关闭标准

### seed

- 默认关闭，环境 ID 缺失或不匹配时拒绝。
- operator token 不匹配时拒绝。
- 数据库访问前完成基础门禁。
- 只有已经存在的 active owner 才能继续。
- 无法创建首个 owner。
- 正式部署 allowlist 不包含 seed 和 T0。

### reserveOrder

- 数量只接受 `1..20` 的安全整数。
- 每单商品行数、备注、ID 和幂等键有上限。
- 重复 SKU 在事务前聚合。
- 商品价格和总金额来自服务端商品快照。
- 商品和时段计数器满足非负与容量不变量。
- 非法请求在过期清理、建时段和订单事务前拒绝。

### Site 商户 API

- 默认关闭。
- 启用时要求平台注入的登录身份。
- 用户 ID 必须位于服务端 allowlist。
- query 和客户端角色 Header 不能授予商户权限。
- 商户读取和写入路由使用同一门禁。
- 数据库 RBAC 上线后替换临时 allowlist。

## 架构决策

1. 原生微信小程序与 CloudBase 业务云函数构成目标生产路径。
2. Site/D1 只作为产品评审 Demo，不承担真实商户后台职责。
3. 后续真实商户后台必须调用与小程序相同的 CloudBase 业务服务。
4. 库存唯一键为 `storeId + businessDate + skuId`。
5. `order_reservations` 是预占事实；库存汇总必须能够由事实重建。
6. 支付回调是支付成功的权威来源，客户端回调只能触发刷新。

## 环境依赖和停止边界

以下动作需要用户提供或确认专用环境后才能执行：

- CloudBase 测试环境 ID、测试 AppID 和云函数部署权限。
- 微信支付测试商户、证书和回调域名。
- Site 受控身份 allowlist。
- 真机设备矩阵和隐私政策正式文本。

在这些条件未满足前，允许继续完成本地代码、迁移、测试工具和 Runbook；禁止声称 T0、支付、并发、真机或生产门禁已通过。
